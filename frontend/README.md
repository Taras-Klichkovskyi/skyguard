# SkyGuard Frontend Web Client (SG-9)

Інтерактивний клієнтський веб-застосунок на базі **Leaflet.js** та **Material Design 3 Dark OLED**, розроблений у межах задачі **SG-9 (5 SP)** (Спринт 2) лідом команди та UI/UX розробником Денисом Пелехом.

Застосунок реалізує інтерфейс безпечного пошуку укриттів, управління згодою на обробку персональних геоданих (Data Governance by Design), перевірки якості геоданих (Data Quality Rules DQ-1, DQ-3), моделювання інцидентів безпеки (403 Forbidden) та верифікації аудиторського сліду (Audit Trail SHA-256).

---

## 🚀 Швидкий запуск

Фронтенд є повністю автономним (SPA без сторонніх бандлерів) та готовим до демонстрації як з локального файлу, так і через будь-який веб-сервер:

### Варіант 1: Через Python HTTP Server
```bash
cd frontend
python3 -m http.server 8085
```
Відкрийте в браузері: [http://localhost:8085](http://localhost:8085)

### Варіант 2: Пряме відкриття
Просто двічі клацніть на файл `index.html` або відкрийте його у браузері Chrome / Firefox / Safari.

## 🛠 Реалізований функціонал (SG-9)

1. **Інтерактивна темна мапа (Leaflet.js + CartoDB Dark Matter)**:
   - Візуалізація 10 верифікованих укриттів м. Львова у форматі **GeoJSON (RFC 7946)**.
   - Динамічні пульсуючі SVG-маркери за статусом готовності:
     - 🟢 **ACTIVE** (зелений) — відкрито, готове до прийому.
     - 🟡 **LIMITED** (жовтий) — обмежений доступ або заповнення >80%.
     - 🔴 **CLOSED** (червоний) — закрито або ремонтні роботи.
   - Фільтрація за статусом, типом укриття (найпростіше, ПРУ, сховище) та інклюзивністю (доступність для МГН).

2. **Data Governance by Design (Керування згодою L1 / L2)**:
   - Індикатор згоди у шапці: «Згода: Відхилено» або «Згода: Надана».
   - Модальне вікно багаторівневої згоди (Notice & Choice) з гранулярним вибором цілей обробки:
     - Обов'язкова мета: маршрутизація до найближчого укриття.
     - Опційна мета: анонімізований краудсорсинг статусу укриттів.
   - Можливість відкликання згоди в 1 клік із фіксацією події `CONSENT_REVOKE` в аудиті.

3. **Геолокація, найближче укриття та маршрутизація (Haversine formula)**:
   - Кнопка швидкого визначення поточної GPS-позиції користувача.
   - Кнопка **«Найближче укриття»**: автоматичний розрахунок відстані за формулою гаверсинусів (Haversine distance) та орієнтовного часу пішого руху (швидкість 5 км/год).
   - Побудова інтерактивної пунктирної лінії маршруту (`L.polyline`) від поточної точки до обраного укриття.

4. **Симуляція сигналу «Повітряна тривога» (🚨)**:
   - Кнопка швидкого переходу в режим тривоги у шапці інтерфейсу.
   - Червоний пульсуючий банер цивільного захисту з підказками першочергових дій.
   - Автоматичний фокус мапи на найближчому відкритому укритті з прокладанням екстреного маршруту.

5. **Краудсорсинг та валідація якості геоданих (DQ-1, DQ-3)**:
   - Форма подання звіту громадянина про статус укриття.
   - **Правило DQ-1 (Геопросторова валідація)**: перевірка, чи знаходиться заявник у радіусі **до 300 м** від геокоординат укриття. У разі спроби подати звіт з іншого району міста — запит блокується з повідомленням про порушення DQ-1.
   - **Правило DQ-3 (Консенсусний кворум)**: симуляція консенсусу (1/3 $\to$ 2/3 $\to$ 3/3). При досягненні 3 незалежних підтверджень статус укриття автоматично оновлюється на мапі без участі адміністратора.

6. **Симуляція безпекового інциденту (403 Forbidden)**:
   - Перемикач ролей у верхній панелі: `Громадянин (Citizen)`, `Комендант (Shelter Owner)`, `Офіцер ДСНС (DSNS Officer)`, `Аудитор безпеки (Security Auditor)`.
   - При спробі змінити офіційні параметри укриття від імені звичайного громадянина відкривається модальне вікно блокування доступу 403 Forbidden з кодом `ERR_RBAC_INSUFFICIENT_PRIVILEGES` та фіксацією спроби несанкціонованого доступу в журналі подій.

7. **Консоль аудитора (Audit Trail SHA-256 Console)**:
   - Панель перегляду незмінного ланцюга подій аудиту (Append-Only Log).
   - Кожна подія містить: `timestamp`, `event_type`, `user_id`, `resource`, `ip_address` (маскований за стандартом GDPR `/24`), `status_code`, `prev_hash` та поточний `sha256_hash`.
   - **Інтерактивна перевірка цілісності**: кнопка перевірки ланцюга криптографічних хешів.
   - **Симуляція спроби зламу**: кнопка спотворення даних у минулому записі — консоль миттєво підсвічує ланцюг червоним та фіксує порушення цілісності: `TAMPER_DETECTED: Hash mismatch at block #2`.

8. **Експорт геоданих (RFC 7946 GeoJSON)**:
   - Можливість завантаження актуального шару укриттів у відкритому форматі `shelters.geojson` для інтеграції з міськими геоінформаційними сервісами.

## 📁 Структура файлів

- `index.html` — розмітка інтерфейсу, шапки, мапи, сайдбару та модальних вікон.
- `styles.css` — таблиця стилів, палітра Dark OLED, анімації радарів і банерів тривоги.
- `app.js` — логіка клієнта, розрахунки відстаней, обробники подій, симуляції консенсусу й аудиту.
- `shelters.geojson` — валідний геопросторовий датасет з 10 укриттями Львова.
